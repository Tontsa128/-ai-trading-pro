# Rahasampo Radar — professional code audit 2026-10-17

## Scope

Reviewed the deployed browser architecture, shared signal engine, Binance REST proxy, browser WebSocket feed, candle WebSocket, 2-hour paper collector, 5s/15s paper worker, persistence workflow, Vercel build filter, legacy Streamlit app, and regression-test suite.

## Fixed in this audit pass

1. **REST market-data caching** — `/api/market` previously advertised a public cache window. It now sends `no-store`, `no-cache`, `must-revalidate`, `Pragma: no-cache`, and `Expires: 0`. The proxy also exposes generation and latest-candle age headers for diagnostics.
2. **WebSocket exchange-time validation** — the Node market-feed parser now validates Binance trade timestamps and, when supplied, book-ticker event timestamps. Future/stale exchange events fail closed and cannot advance the short-horizon paper bars.
3. **Live/browser freshness model** — existing browser feed keeps trade-price age separate from bid/ask age and blocks actionable signals when the stream is stale or disconnected. The candle stream has an idle watchdog and endpoint rotation.
4. **Signal policy consistency** — the browser, historical test and 2-hour paper collector use the same shared `trading-engine.js` source and evaluator. The strategy is explicitly long-only spot; bearish state means avoid new buys, never short.
5. **Over-filtering** — `spot-long-v29` replaces the previous all-or-nothing technical gate with a scored entry gate while retaining hard data, trend, risk and cost guards. At least one higher timeframe can confirm a long setup; a bearish higher timeframe blocks it.
6. **Diagnostics** — entry score, RSI range, ADX/DI+/DI−, spread precision, live price timestamp and data-age states are exposed. Small OOS samples are shown with a warning rather than hidden.
7. **Historical causality** — higher-timeframe bars are aligned to the main candle close time and the backtest enters on the next main candle open, avoiding look-ahead through a future higher-timeframe candle.
8. **Vercel stale-build protection** — deployment headers are no-store and the ignore-build script keeps paper telemetry commits off the deployed artifact. This prevents report commits from pretending to be application deployments.

## Important findings that are intentional, not bugs

- Absolute zero-latency cannot be guaranteed over the public Internet. The browser reports observed receive age and fails closed after configured thresholds.
- The 5s/15s worker is a separate research strategy and is not the same strategy as the main 1h/4h/1d engine.
- GitHub Actions schedules are not a 24/7 execution server. Their reports can be hours old when a scheduled run has not occurred; the browser live price/candle stream is independent of those reports.
- Historical spread is estimated because historical order-book snapshots are not stored.
- No real exchange order execution, account balance access, private keys, or live-money trading is enabled.
- `app.py` is a legacy Streamlit interface and intentionally has a separate heuristic scoring model; it is not the Vercel browser engine.
